Q11. Assets and adversaries (5 marks).
A faculty member places an encrypted examination package in a shared
directory. An adversary can read, replace, remove, duplicate and delay any
file in that directory, but cannot access either participant's private keys
or alter the recipient program. The sender and recipient have already
exchanged authentic public keys.
(a) Identify three protected assets and distinguish confidentiality from
integrity for this scenario (2).
(b) Describe one modification attack and the check that should reject it
(1).
(c) Explain whether the implementation prevents deletion or delayed delivery
(1).
(d) Explain what changes if the trusted sender public key can be replaced
(1).
Q12. Meaning of successful verification (5 marks).
A coordinator reports that a package's signature and GCM tag verified. A
colleague concludes that the paper is recent, was approved by the
examination committee, and has never been processed before.
(a) State precisely what successful signature verification establishes
relative to a pinned public key (2).
(b) Assess each of the three conclusions separately, naming information or
state the application would need to justify it (2).
(c) Explain why an authenticated timestamp alone cannot establish that a
package has not previously been accepted (1).
Support answers with the stated adversary model; do not assume an online
authority, clock policy or replay database.

Q13. Educational RSA calculation (5 marks).
For this question only, use textbook RSA with p=11, q=17, public exponent
e=7 and message integer m=8. These deliberately tiny parameters are for
arithmetic practice and must never be used by the application.
(a) Calculate n and Euler's phi(n) (1).
(b) Use the extended Euclidean algorithm to find a positive private exponent
d such that ed is congruent to 1 modulo phi(n) (2).
(c) Calculate c=m^e mod n, showing repeated-squaring intermediate residues
(1).
(d) Describe the modular operation that recovers m and explain why this
exercise is not a secure file-encryption design (1).
Q14. Role separation (5 marks).
Two participants each possess an RSA-4096 pair. List the four keys with an
unambiguous owner and public/private designation.
(a) Map signing, verification, session-key wrapping and unwrapping to those
keys (2).
(b) Explain why transferring the recipient private key to the sender is
unnecessary (1).
(c) Explain why a recipient public key cannot decrypt an OAEP-wrapped
session key (1).
(d) A developer proposes signing with the recipient private key instead.
Explain which claimed identity the resulting signature would bind and why it
fails the workshop's sender-authentication objective (1).
Show all numerical work. Modular reductions may be performed with a non-

Q15. RSA capacity and message encoding (5 marks).
Use the OAEP maximum message length formula mLen <= k - 2*hLen - 2, where k
is the RSA modulus length in bytes and hLen is the hash output length in
bytes. Take RSA-4096 and SHA-256, whose output is 32 bytes.
(a) Calculate k and the maximum OAEP message length (2).
(b) Determine whether a 32-byte AES key fits and whether a 2 MiB examination
file fits (1).
(c) Explain how hybrid encryption handles that file without splitting it
into raw RSA blocks (1).
(d) State the OAEP hash, MGF1 hash and label policy used by this project
(1).
Q16. Digital signatures (5 marks).
The application uses RSA-PSS with SHA-256, MGF1-SHA256 and a 32-byte salt.
An engineer proposes replacing the signature with a plain SHA-256 digest
stored beside the ciphertext.
(a) Explain how an attacker able to modify the package could also update
that plain digest (2).
(b) Explain what possession of the sender private key contributes to RSA-PSS
signing (1).
(c) Explain why the signature must include the encrypted session key and
recipient identifier as well as the ciphertext (1).
(d) Distinguish the purposes of OAEP randomness and PSS salt; neither should
be described as a password (1).
Do not implement OAEP or PSS arithmetic; reason about the library interfaces
and their security roles.

Q17. Encryption and authentication workflow (5 marks).
An AESGCM encryption call returns ciphertext followed by a 16-byte
authentication tag. The plaintext is 6,000 bytes, and associated metadata is
serialized separately as AAD.
(a) State the ciphertext length and combined return-value length (1).
(b) Explain whether AAD is encrypted and why it is nevertheless
authenticated (1).
(c) Give the input values that the recipient must supply to reproduce the
authentication check (2).
(d) Explain why writing tentative plaintext before the library confirms
authentication violates the acceptance requirement (1).
Q18. Randomness and collision reasoning (5 marks).
For independent uniformly random values in a space of size N, use the small-
probability birthday approximation P(collision) approximately q(q-1)/(2N).
For this calculation only, consider q=2^20 messages encrypted under one
fixed key with independently sampled 96-bit nonces.
(a) Give N and estimate the collision probability as a power of two (2).
(b) Explain why reusing a nonce with the same GCM key is dangerous even if
both messages are signed (1).
(c) Contrast this hypothetical fixed-key system with the application's fresh
256-bit key for every encryption (1).
(d) Explain why two observed different ciphertexts alone do not prove that
fresh session keys were generated (1).
State the approximation used and distinguish an observed test result from a
mathematical guarantee.

Q24. Filesystem scenarios (5 marks).
